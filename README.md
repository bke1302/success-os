# Success OS

A habit and goal tracking web app with an AI coach. It scores every day by what actually moved the needle, tracks streaks with earned "freezes", and gives blunt end-of-day feedback generated by Claude. Hebrew, RTL-first UI.

**Live:** https://flowopsai.co.il/success-os/

## Features

- **Daily success score** — habits are split into *output* (job applications, outreach, deep work) and *input* (learning, reading, exercise). Output is weighted at 60% of the score, and a day with zero output actions is capped at 40% — learning alone never counts as a successful day.
- **Streaks with earned freezes** — averaging 80%+ over a week earns a streak freeze (up to 2 banked), which is consumed automatically to protect the streak on a missed day.
- **MIT (Most Important Task)** — one task per day that defines whether the day was a win.
- **Focus timer** — preset deep-work sessions; completed minutes are banked into daily and all-time focus stats.
- **Evening journal + AI coach** — a short journal entry is sent to Claude together with the day's score, habit completion, current streak, and the last 7 days of history. The coach replies with what worked, where you slipped, and three concrete tasks for tomorrow. Without AI configured, a built-in rule-based coach generates the feedback instead.
- **Time-aware layout** — the home screen reorders itself for morning (plan the MIT), midday (score front and center), and evening (review and close the day).
- **Fully editable checklist** — habits can be added, renamed, or removed; new defaults merge into existing data without wiping progress.
- **Local-first data** — everything lives in `localStorage`. No account, no backend database. One-click JSON export/import for backup.

## Architecture

The repository contains two implementations of the app:

| Path | What it is |
|------|-----------|
| `app/` | **The version deployed in production** — a single self-contained HTML file (vanilla JS, zero dependencies, no build step), published to GitHub Pages by the CI workflow. |
| `src/` + `worker/` | The full React 19 + TypeScript codebase (Vite, Tailwind, PWA) with a Cloudflare Worker that proxies AI requests. |

### AI coach and API key security

The React codebase never exposes an API key to the browser. The client only knows the URL of a Cloudflare Worker (`worker/claude-coach.js`); the Anthropic key is stored as a Worker secret on the server side:

```
+------------------+        POST { prompt }        +---------------------+
|  Browser client  | ----------------------------> |  Cloudflare Worker  |
|  (no API key)    | <---------------------------- |  claude-coach.js    |
+------------------+        { response }           +----------+----------+
                                                              |
                                            x-api-key from Worker secret
                                            (never shipped to the client)
                                                              |
                                                              v
                                                   +---------------------+
                                                   |    Anthropic API    |
                                                   |  /v1/messages       |
                                                   +---------------------+
```

The Worker validates the request, forwards only a minimal `{ prompt }` payload to the Claude API, and returns only the generated text — so the key can be rotated or rate-limited in one place and never appears in client code, network logs, or the deployed bundle.

The single-file production version takes a different, deliberately serverless approach: the AI coach is opt-in bring-your-own-key. The user pastes their own Anthropic key in the Profile tab; it is stored only in their browser's `localStorage` and sent only to the Anthropic API. With no key configured, the offline rule-based coach takes over.

### Deployment

Pushing to `main` triggers a GitHub Actions workflow (`.github/workflows/deploy.yml`) that publishes the `app/` directory to GitHub Pages, served under the custom domain `flowopsai.co.il`.

## Tech Stack

- **Production app:** vanilla JavaScript, single HTML file, `localStorage` persistence
- **Full codebase:** React 19, TypeScript, Vite, Tailwind CSS, `vite-plugin-pwa`
- **AI:** Claude (Anthropic API), proxied through a Cloudflare Worker
- **Sync (optional):** Supabase — code-based push/pull backup of app data
- **CI/CD:** GitHub Actions to GitHub Pages

## Development

The production single-file app needs no tooling — open `app/index.html` in a browser.

For the React codebase:

```bash
npm install
npm run dev        # dev server at http://localhost:5173
npm run build      # type-check + production build
npm run preview    # preview the production build
```

To deploy the AI proxy:

```bash
cd worker
wrangler deploy
wrangler secret put ANTHROPIC_API_KEY
```

Then paste the Worker URL into the app's profile screen.
